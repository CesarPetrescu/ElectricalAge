### ELN-1 — Capacitor telemetry reports zero during real charging (confirmed, medium)

Location: `src/main/java/mods/eln/sim/mna/component/Capacitor.java`, current getter. Consumer: `PowerCapacitorElement.multiMeterString`.

Reproduction uses the actual MNA solver: 10 V ideal source, 100-ohm resistor, 1 mF capacitor, first 0.01 s backward-Euler step. Capacitor voltage is 0.909090909 V. Therefore `C * deltaV / dt` is **0.09090909090909091 A**; the resistor reports **0.09090909090909093 A**. The capacitor reports **0 A**, because its getter returns a constant zero.

Impact: the capacitor's instrument current is false while charging/discharging. The RC voltage trajectory passed both the first-step and 100-step analytical checks, so this result does NOT establish that the capacitor's voltage solver is broken.

Suggested correction: retain the signed current of the completed solver step using the actual timestep and voltage history. Test charge, discharge, steady state, variable stepping and meter output; do not recompute against an already-updated history value that makes deltaV zero.

### ELN-2 — A zero-ohm resistor creates infinite conductance (confirmed boundary defect, medium)

Location: `src/main/java/mods/eln/sim/mna/component/Resistor.java`, `setResistance`.

Set a valid resistor to 10 ohms, then call `setResistance(0.0)`. Observed `R=0.0` and `resistanceInverse=Infinity`. The current validation does not reject finite zero before calculating `1/R`.

Impact: malformed or incorrectly constructed components can supply non-finite conductance to the circuit system. This audit proves the invalid component state; it does not prove ordinary gameplay always reaches it, nor did it reproduce a normal-world crash from this call.

Suggested correction: reject nonpositive resistance, or use an explicitly documented finite short-circuit floor where appropriate. An intended ideal short should have an intentional solver representation, not accidental division by zero. Include zero, negative, NaN/infinity and extreme-value tests while preserving ordinary Ohm's law.

### ELN-3 — Missing resistor NBT silently creates the same invalid state (confirmed persistence boundary, medium)

Location: `src/main/java/mods/eln/sim/nbt/NbtResistor.java`, `readFromNBT`.

Start with a valid 10-ohm resistor and read an empty `CompoundTag`. An absent R value reads as zero and is passed into the setter. Observed `R=0.0`, inverse resistance `Infinity`.

Impact: missing/partial/migrated data can transform a safe component default into the invalid state from ELN-2. This is not evidence that normal valid saves are corrupted: an independent 470-ohm NBT roundtrip passed, as did the broader real saved-world restart suites.

Suggested correction: validate presence, numeric tag type, finiteness and allowed range. Preserve a safe default for missing values and diagnose/recover invalid persisted values. Fixing the setter alone must not turn malformed-world loading into an unhandled exception.

## Qualifications and priorities

Development gallery logs include some missing dev/hidden item models and headless audio-device/narrator warnings. These were not reproduced as visible released-item texture failures or listening-quality defects; packaged client logs show successful null-output audio initialization. They should not be counted as proven player-facing bugs without a corresponding runtime reproduction.

Not performed: long-duration large-world soak, WAN latency/loss, every optional modpack, real GPU driver matrix, subjective listening or physical-system validation against laboratory measurements. Counts from repeated phases are not unique feature counts.

Prioritize safe resistor setter/NBT handling together, then accurate capacitor instrumentation. Preserve the independent failing tests as the acceptance criteria. Both repositories have substantial working runtime coverage, but a green pre-existing suite does not invalidate these new reproducible defects.
