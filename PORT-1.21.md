# Porting Electrical Age to Minecraft 1.21.1 (NeoForge)

Branch `port/1.21.1`, based on `port/1.12.2` (which is upstream `main` @ `6a8cd0df` plus the 1.12.2
port). The 1.12.2 branch is the base because it already did the API modernisation that 1.21 also
needs (BlockPos, ItemStack.EMPTY, capabilities, deferred registration, lowercase assets, model
JSON) and because its `McBridge`/boundary-class discipline is what keeps this port tractable.
`PORT.md` is the 1.12.2 document; the layers it describes are reused here where they still apply.

## Fixed decisions

| Topic | Decision |
| --- | --- |
| Loader | **NeoForge 21.1** (gradle.properties: `neoVersion`). Forge 1.21 has no Kotlin language provider; the 1.21.1 ecosystem (Jade, JEI, CC:Tweaked, FE consumers) is NeoForge. |
| Build | ModDevGradle 2.0.x on Gradle 9.2 / JDK 21, Mojmap + Parchment. `tools/port/env.sh` sets JAVA_HOME. |
| Kotlin | **Kotlin for Forge 5.x** provides the runtime (`modLoader="kotlinforforge"`); no shading, no relocation. The Kotlin Gradle plugin is pinned to the exact stdlib version KFF bundles (5.12.0 -> Kotlin 2.4.0). |
| Mod entry | `Eln.java` stays a Java `@Mod` class; KFF's container constructs it with `(IEventBus, ModContainer)` injection. |
| Compile set | An explicit include list (`tools/port/include-1.21.txt`, one Ant pattern per line) drives what compiles. Everything else stays in the tree untouched until ported. `./gradlew portStatus` is the metric. |
| The Flattening | Every descriptor is its own registered `Item` (`DescriptorItem`/`DescriptorBlockItem`), named by the same `registryName()` sanitizer as 1.12.2. The families (`GenericItemUsingDamage`, `GenericItemBlockUsingDamage`) are no longer `Item`s; they register their descriptors' items and keep `getDescriptor(stack)` and the legacy-id table so call sites survive. Ores are one block per descriptor. No data-component encoding of descriptor ids: recipes, tags and JEI key on item identity. |
| Registration timing | NeoForge freezes the registries outside `RegisterEvent`, and an `Item`/`Block` cannot even be constructed while frozen (intrusive holder). So descriptors are constructed eagerly and in order; registry objects are staged in `ElnRegistry` as factories and created inside their event; anything needing an `ItemStack` at construction time goes through `ElnRegistry.afterItems`. Vanilla event order: blocks, items, block entity types, creative tabs. |
| Lang | The `.lang` files stay the source (generated from `tr()` call sites). `generateLangJson` converts them to `en_us.json` etc. at build time, keys byte-for-byte (including `\:` escapes, which `I18N.tr` looks up as-is). Items keep the 1.7.10 key shape: `DescriptorItem.getDescriptionId()` returns `Copper_Dust.name`. |
| Item models | Generated by `runData` (`mods.eln.datagen`) from the registered items: `item/generated` with the icon, and the voltage-level background as `layer0` where the descriptor has one. 3D items get a `BlockEntityWithoutLevelRenderer` in phase 3. |
| Textures | Kept under `textures/items/`, `textures/blocks/`, `textures/voltages/` (1.12 layout). 1.19.3+ only stitches the directories listed in `atlases/blocks.json`, so `assets/minecraft/atlases/blocks.json` adds those three sources. |
| World compat | None (fresh worlds only); nothing from 1.7.10/1.12.2 saves is migrated. |
| Packets | Unchanged byte protocol, wrapped in one `CustomPacketPayload` (phase 2). |
| Rendering | Rewrite (phase 3): `Obj3D` bakes vertex lists replayed into a `VertexConsumer`; the fixed-function matrix/state calls go through a `PoseStack`-backed facade so the ~150 `draw()` bodies keep their shape. |

## Phases

0. Toolchain and the flattening pattern end-to-end: MDG build, KFF, `Eln` entry, `ElnRegistry`,
   families + per-descriptor items, ores as blocks, datagen, lang JSON, server boot, headless
   client to the title screen. **Done** (see Status).
1. The rename pass over the whole tree (Mojmap column in `rewrite.pl`), then grow the include list
   package by package with the rendering and GUI code behind facades; sim core and its tests first.
2. Flattened content registration (`ItemRegistration`, the node registrations, armor/tools),
   recipes via datagen from `CraftingRecipes.kt`, tags from the ore-dictionary names, worldgen
   JSON, config, SavedData, networking wrapper, entities, sounds, fluids -> dedicated server runs
   a circuit (smoke test ported to the GameTest framework).
3. Rendering: Obj3D backend, `BlockEntityRenderer`s, the item renderer, camouflage via
   `ModelData`; then the GUI layer (`Screen`/`GuiGraphics`/`AbstractContainerMenu`).
4. Capabilities (fluid/item/energy on the node entities), Jade, CC:Tweaked, fluids' buckets.

## Things deliberately left for a later phase (grep `phase` in the sources)

- `Eln.uiIconsNoSymbols()` returns false until `JsonConfig` is ported (phase 1).
- `CreativeTabPopulator` no longer reorders regulator chips after DC/DC converters; comes back with
  the node families (phase 1).
- `VoltageLevelColor.fromCable(...)` moved out of the enum (it referenced the cable descriptors);
  the 8 call sites get `descriptor.voltageLevelColor` in phase 1. `setGLColor()` is `rgb` now and
  is applied by the phase-3 render facade.
- `Item.onBlockStartBreak` no longer exists on NeoForge: the descriptor hook is driven from
  `BlockEvent.BreakEvent` once the event handlers are ported (phase 1).
- `GenericItemUsingDamageDescriptor.getNbt()` returns a copy (data components are immutable in
  place); the 14 item-NBT call sites switch to `updateNbt {}` when their files are included.
- Ore loot tables, worldgen features and `c:` tags are datagen work in phase 2; until then an ore
  block drops nothing.

    ./gradlew build          compiles the include set
