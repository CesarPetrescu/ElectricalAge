## Functional scope added

The first milestone had one independent internal circuit bench. This handoff retains that bench and adds four connected prototype blocks: `eln:voltage_source`, `eln:resistive_wire`, `eln:resistive_load`, `eln:capacitor`.

Source: 10 V with 1 ohm internal resistance. Load: 10 ohms. Capacitor: 1 F. Each six-way wire arm is 0.05 ohm. Source/load/capacitor have two opposite terminals along their facing axis. A full return path is required; independently connected islands do not share a hidden ground. All use the inherited MNA solver, not a generic energy counter. Timestep is 0.05 seconds per server tick.

A per-level, server-thread-only manager consumes actual vanilla BlockEntity tick heartbeats, rebuilds changed topology, preserves differential capacitor history, and removes inactive device references without force-loading chunks. Sources toggle without rebuilding unchanged topology. The load emits light based on calculated electrical power. Numerical failure in one constructed island is isolated from others; a level-wide topology construction failure can freeze all devices participating in that rebuild.

The small 3x3 demonstration ring has six wire blocks, a source and a load. Its resistance is 11.6 ohms, so the predicted load current is 0.8620689655 A and load voltage 8.620689655 V. Real GameTests verify that loop, removal/reconnection of a wire, capacitor charging/continuation across graph rebuilds, and source-off discharge.

The new devices use deliberately simple full-cube models and vanilla textures. The independent bench retains its original adapted OBJ artwork. No complete SixNode or historical machine renderer is claimed.

## Reproduced defects and hardening

- Singular subsystem solves previously overwrote existing voltages with zero; failed solves now reject publication and retain last good readings.
- Nonfinite RHS values or accumulated overflow are rejected; solution publication waits for a complete finite result.
- PowerSource could register its RHS callback twice and solve a configured 3 V source as 6 V. Duplicate registration is removed and regression-tested.
- VoltageSource and Inductor removal now detach private current states and callbacks. Closed subsystems reject reuse; null/duplicate/foreign-state registrations are guarded.
- Capacitor current is calculated instead of always returning zero, and explicitly seeded differential history survives reference/topology changes and bench resets.
- Bench runtime fault latches now survive save/load (schema 2, with valid schema 1 reads); strict booleans and unsupported/corrupt-state retention are tested.
- Component voltage/current restoration is atomic: a bad current cannot leave only the new voltage applied. Inductor nonfinite restored current is rejected.
- Explicit failed matrix regeneration cannot leave a stale pending result publishable; inconsistent state IDs and null/closed callback registration are rejected.
- Removed entities cannot interact/advance; the bench closes on unload callbacks. Rotation/mirror, packet target checks and vanilla build/interact permissions are handled.
- Package version derives from Gradle; new resources and all facing/light variants have validation. The historical extraction script is disabled to prevent overwriting subsequent fixes. Offline checks are cross-platform Python plus JDK 21.

The final rescan added seven core hardening tests which failed before their fixes and passed afterward. Those are API/edge-case regressions, not seven independently observed gameplay crashes.

## Remaining work / limits

This is **five prototype blocks, not the complete Electrical Age port**. Guards currently limit connected devices to **64 active devices per server level**, **128 MNA unknowns per island**, and **1024 core branches**. A matrix budget can be reached before 64 blocks. Limits are safety guards, not performance guarantees.

Breaking/replacing a capacitor or bench resets item-carried charge. Inactive/unloaded capacitor state is frozen; there is no offline catch-up. Full machine inventories, automation capabilities, SixNode interactions, thermal/mechanical systems, advanced animations, survival progression, supported third-party integrations and legacy-world migration remain unported.

Next acceptance gates: ordinary populated-server save/restart, actual chunk-boundary unload/reload with charged capacitors, two-client edits, dimension transitions and claim-mod permissions. Then graph reduction/performance work and complete machine vertical slices. The legacy core still exposes some mutable collections/utilities; tested guarded paths are not a proof against arbitrary API misuse.

Use a disposable new NeoForge 1.21.1 / Java 21 profile. Do not place this JAR in Forge 1.12.2 or open old ELN worlds. Read ports/1.21.1/HANDOFF.md before continuing.
